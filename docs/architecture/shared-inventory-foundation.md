## 5. Balance model

Evidence (`MANUFACTURING AGENTS.md`; `MANUFACTURING modules/Ledger/LedgerMaintenance.php`; `MANUFACTURING modules/Ledger/migrations/001_stock_ledger_entries.sql`):

Manufacturing existing mechanism (`MANUFACTURING modules/Ledger/LedgerMaintenance.php`):
- Immutable entries created (`INSERT`) with `created_at` timestamp.
- Ordered sequence (`ORDER BY created_at ASC, id ASC`) used for derivation.
- `rebuildFromSources()` reads Manufacturing execution modules; creates entries; deletes Manufacturing-specific source entries when resetting (not universal deletion — Manufacturing-specific rebuild only).
- `recalculateBalances()` updates `balance_after` sequentially per `product_id`; balance is derived running total, not persisted independently.
- `rebuildForProduct()` filters by Manufacturing `product_id` and rebuilds Manufacturing-specific entries.
- Historical audit preserved in Manufacturing-specific entry sequence.

Design recommendation for universal inventory: `immutable universal ledger entries + derived universal balance` (same model as Manufacturing mechanism but universal scope, universal categories, universal adapter/service contracts feeding Manufacturing effects).

Why this model (not direct quantity overwrite):
- Manufacturing mechanism already demonstrates derived balance from ordered sequence.
- Direct overwrite of universal quantity by Manufacturing controllers/services (without universal adapter contracts) violates universal inventory independence; Manufacturing must reference universal inventory through adapter contracts, not silently overwrite universal balance directly.
- Historical auditability must be preserved (Manufacturing `MANUFACTURING modules/Ledger/LedgerMaintenance.php` rebuild preserves Manufacturing source sequence; universal audit must preserve universal sequence; Manufacturing adapter/service contracts must maintain Manufacturing source references when feeding universal inventory).
- Idempotency/deduplication requires universal unique key (recommended: universal `source_domain` + `source_transaction_ref` + universal `movement_type` + `item_ref` + `warehouse_ref` — ensures Manufacturing effects mapped through adapter contracts are not duplicated in universal inventory).
- Reversal/correction requires universal adjustment mechanism (`ADJUST` category with universal `before_qty`, `after_qty`, `reason_ref`, `author_ref`); Manufacturing `MANUFACTURING modules/Ledger/Controllers/LedgerController.php` (`/ledger/add`) provides Manufacturing-specific adjustment mechanism; universal adjustment mechanism must be independent but must reference Manufacturing adapter contracts when Manufacturing adjustments are mapped.
- Failure semantics: universal inventory adapter/service contracts must declare failure behavior when Manufacturing adapter/service contracts are unavailable/unpromoted (Manufacturing core must continue independently; universal adapter must return graceful `null`/empty when Manufacturing adapter unavailable; no hard failure in Manufacturing core when universal inventory unavailable; universal inventory adapter/service contracts must declare this behavior explicitly).
