## 1. Final Architecture Statement

The architecture remains the **modular monolith** described in `docs/architecture/current-ownership-inventory.md` Section 2 and `docs/architecture/odarehub-productization-roadmap.md` Section 1: one PHP repository/deployment unit with `app/` (Core), `platform/` (engines/governance), `plugins/` (technical providers), `apps/` (business apps), `shared/` (prototype skeletons only), `work/` (unmerged branches), and `storage/` (runtime artifacts, not shared schemas).

The canonical target vocabulary (`system_app`, `domain_app`, `shared_app`, `module`, `plugin`, `package`, `suite` as legacy) is frozen per roadmap Section 2.

No current evidence justifies promoting `Shared\Item` (prototype skeleton, 0 runtime consumers) or `Apps\Parties` (prototype skeleton, 0 runtime consumers, empty `routes.php`, no `core_apps` entry, no production `party_id` FK) to `shared_app`. Manufacturing Products (`Plugins\Products\Services\PartItemRefService`) remains Manufacturing-owned (`Plugins\` namespace convention preserved; `item_ref` is Manufacturing-local opaque reference to Manufacturing `products` table; `require_once` restored in Milestone 2; no namespace change).

No universal Inventory authority exists on `main`. Manufacturing `Plugins\Ledger` (product-level `stock_ledger_entries`), Manufacturing `Plugins\MaterialManagement` (`material_ledger` with Manufacturing-specific movement/reservation rules), Manufacturing `Plugins\DispatchEntries` (`dispatch_entries` — Manufacturing workflow), Manufacturing `Plugins\DailyOrders`/`Plugins\PreOrders` (Manufacturing planning), Manufacturing `Plugins\QRCode` (integration adapter feeding Manufacturing Ledger), Manufacturing `Plugins\Products` (read-only `stock_ledger_entries` reference for display), Procurement (`Apps\Procurement` — `procurement_purchase_orders`/`lines`/`receipts`/`requests`/`suppliers`), SBAIO (`Plugins\Sales` — `sbaio_sales`), and Hospitality (`Apps\Hospitality` — `hosp_rooms`/`guests`/`reservations` capacity, not inventory stock) each own independent inventory/commercial schemas. `work/shared-inventory-foundation/` remains unmerged on `main`. `docs/architecture/current-ownership-inventory.md` confirms `DOMAIN-OWNED` for Inventory; `docs/architecture/parties-data-model.md` confirms `DOMAIN-OWNED` for party-like identity.

No universal Commercial authority exists. Procurement owns `procurement_purchase_orders`; Manufacturing owns dispatch/daily orders/pre-orders; SBAIO owns `sbaio_sales`; Manufacturing Ledger reconciles Manufacturing sources (`ProductionEntries`, `DispatchEntries`, `QCEntries`, `QRCode`); `work/shared-commercial-foundation/` remains unmerged; `docs/architecture/current-ownership-inventory.md` confirms `INSUFFICIENT EVIDENCE` / `DOMAIN-OWNED` status for Commercial.
