# Visual Customizer Approval Request Artifact Plan

Status: planning only. No request button, approval implementation, apply workflow, registry I/O, runtime CSS generation, Shell consumption, Core change, ThemeTool change, or public asset output in this slice.

This plan defines the future artifact shape for a Visual Customizer approval request after a valid Studio-local `radius.scale` draft exists and before any approval or apply workflow runs.

## Purpose

The approval request artifact is a Studio-owned review package.

It records the exact draft value, diff summary, validation status, and non-runtime flags that a future reviewer would inspect. It is not runtime truth and it is not an approved style registry value.

## Artifact Owner And Storage Boundary

Owner: Studio.

Future storage should remain under a Studio-owned workflow path, separate from:

- Platform StyleRegistry active/default truth.
- Shell socket catalog runtime consumption.
- generated `public/assets`.
- app/module owned runtime CSS artifacts.
- Core runtime primitives.

The artifact may reference the Studio-local Visual Customizer draft by id and fingerprint, but it must not copy unknown draft fields into review truth.

## Required Fields

The first artifact version must include:

- `request_id`: unique immutable request identifier.
- `draft_id`: the Studio-local draft id, currently `visual-customizer-local-preview`.
- `draft_fingerprint`: digest of the normalized draft payload used for request validation.
- `requested_by`: authenticated requester identity.
- `tool_id`: `customization-studio.visual-customizer`.
- `selected_socket_id`: exactly `radius.scale`.
- `socket_label`: `Corner scale`.
- `advanced_token`: `--radius-scale`.
- `default_value`: catalog default value for `radius.scale`.
- `current_value`: `Not connected yet` until runtime registry read is explicitly authorized in a later phase.
- `proposed_value`: the validated Studio-local draft value.
- `diff_summary`: regenerated from `default_value` and `proposed_value`.
- `validation_status`: `passed`, `failed`, or `not_run`.
- `status`: initially `pending_review`.
- `created_at`: request creation timestamp.
- `non_runtime_flags`: explicit proof markers that no runtime boundary was crossed.

## Field Rules

`request_id`:

- Must be generated by Studio workflow.
- Must not be reused for a new draft.

`draft_id`:

- Must match the known Visual Customizer local draft id.
- Must not point to Platform registry state.

`requested_by`:

- Must come from the authenticated actor.
- Must not imply approval authority.

`selected_socket_id`:

- Must equal `radius.scale` for this phase.
- Any other socket id must block artifact creation.

`default_value`:

- Must come from Shell socket catalog metadata.
- Must not be read from Platform registry or runtime CSS.

`current_value`:

- Must remain `Not connected yet`.
- Must not be inferred from live CSS, Platform registry, Shell runtime, or public assets.

`proposed_value`:

- Must come from `values.radius.scale.proposed_value`.
- Must be one of the allowed `radius.scale` choices.

`diff_summary`:

- Must be regenerated server-side from validated request inputs.
- Must not be accepted from client text as source truth.

`validation_status`:

- Must be `passed` before status can become `pending_review`.
- A failed validation should prevent request artifact creation unless a future diagnostic-only failure artifact is explicitly planned.

`status`:

- Initial value is `pending_review`.
- This plan does not define approval, rejection, apply, or rollback transitions.

`non_runtime_flags`:

- Must explicitly state that runtime is untouched.
- Must not be used as proof if validation did not run.

## Validation Inputs

Artifact creation should be allowed only after these checks pass:

- authenticated requester
- Studio route/tool authorization
- valid Visual Customizer draft schema
- exact socket id `radius.scale`
- allowed proposed value
- draft fingerprint computed from normalized allowed fields only
- diff summary regenerated from trusted values
- Platform StyleRegistry not read or written
- Shell runtime not connected
- Apply disabled
- public assets untouched
- Core untouched
- ThemeTool untouched

## Explicit Non-Goals

This artifact plan does not authorize:

- request button UI
- approval queue UI
- approval/rejection status transitions
- Apply enablement
- Platform StyleRegistry reads or writes
- Shell runtime draft consumption
- runtime CSS output
- public asset publishing
- non-radius socket inclusion
- Core changes
- ThemeTool changes
- app/module CSS mutation

## Relationship To Request Approval Boundary

The request-approval boundary defines when and why a future request may be made.

This artifact plan defines what the future request package should look like once that boundary is crossed.

Both plans preserve the same invariant: a request artifact is review evidence only. It does not approve, apply, publish, or activate a style value.
